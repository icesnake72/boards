# wiki-sync: LLM Wiki 동기화 (on-demand)

방금 끝낸 작업을 `docs/lecture/` 강의 위키에 **빠짐없이, 코드와 일치하게** 반영하는 절차.
매 턴 자동으로 도는 것이 아니라, 사용자가 명시적으로 요청할 때만 실행한다.

## 사용 조건

- **사용**: "이번 작업 위키에 반영해줘", "단계 N 문서화해줘", "wiki-sync",
  기능/정책/시그니처를 바꾼 뒤 그 변경을 강의 문서에 남기고 싶을 때
- **사용 금지**: 매 턴 자동 실행 금지(사용자가 과거에 "매 턴 도는 Stop hook은 낭비"라고
  명시적으로 거부함). 오타·주석만 고친 경우, 코드와 무관한 잡일에는 쓰지 않는다.

## 핵심 원칙

> **코드가 정본(source of truth)이다.** 문서가 코드와 어긋나면 문서를 고친다.
> 인용하는 코드 스니펫은 반드시 `Read`로 실제 파일을 확인한 뒤 현재 시그니처와
> 일치시킨다(수강생이 그대로 따라 쳐서 컴파일되어야 한다).

## 절차

1. **변경 파악**: 무엇이 바뀌었는지 확정한다.
   - `git log --oneline -10`, `git diff --stat`, 대화 맥락으로 이번 작업 범위를 정리한다.
   - 바뀐 소스 파일과 그 시그니처를 `Read`로 직접 확인한다(감사 없이 기억에 의존 금지).

2. **대상 문서 결정**:
   - **새 단계/새 도메인** → `docs/lecture/`에 새 문서 생성.
     복잡도가 높으면 `lecture-design` 에이전트에 위임해 강사·학생 수준 자료를 만든다.
   - **기존 단계의 기능/정책/시그니처 변경** → 해당 기존 문서를 갱신.
     그 변경이 **다른 단계 문서의 스니펫**에도 영향을 주면(예: 공통 DTO 시그니처 변경)
     그 문서들도 함께 손본다 — "이후 단계가 바꾼 시그니처가 이전 단계 문서에
     역반영 안 되는" 불일치가 이 프로젝트의 주요 실패 모드다.

3. **문서 작성/갱신** — 문서 스타일 규칙(md-docs 계열)을 반드시 지킨다:
   - **ASCII 박스 그리지 말 것**(`┌ ┐ └ ┘ │ ─` 등 금지). 구조는 표·mermaid로.
   - mermaid: 노드 라벨은 `["..."]`, `sequenceDiagram` 메시지에 콜론(`:`) 금지,
     participant alias에 콤마 금지.
   - 코드/명령 블록 들여쓰기 **스페이스 2칸**(탭 금지).
   - 섹션 번호 + `---` 구분자 등 기존 문서 포맷을 따른다.
   - **교육 순서상 의도된 차이는 보존**한다(예: "단계 2 초기 버전 → 단계 4 보강").
     이런 경우 초기 스니펫을 그대로 두되, 이후 개선을 별도 소절/각주로 연결한다.

4. **frontmatter**: 새 문서엔 상단에 아래를 추가한다(기존 문서 형식과 동일하게).
   ```yaml
   ---
   step: <번호>            # 단계에 매이지 않는 이론/참조 문서는 생략 가능
   track: auth | domain    # 트랙 분류
   tags: [<주제 태그들>]
   requires: ["[[선수문서]]"]   # 본문 [[위키링크]]와 함께 그래프의 원천
   status: 완료 | 진행중
   ---
   ```

5. **000-MOC.md 갱신**(새 단계일 때 필수):
   - `§2 단계별 목차` 표에 한 줄 추가.
   - `§1 전체 의존 지도`(mermaid)에 새 노드+엣지 추가.
   - 필요 시 `§3 트랙별 보기`, `§5 태그` 반영.
   - 모든 `[[위키링크]]`가 실제 파일을 가리키는지(깨진 링크 0) 확인한다.

6. **정합성 확인**(경량 감사):
   - 인용 스니펫의 클래스명·메서드명·시그니처가 실제 코드와 일치하는지 재확인.
   - 넓은 변경이면 트랙별로 `Explore` 에이전트를 병렬로 띄워 "문서 서술 ↔ 코드"를
     대조하고 불일치만 보고받는다(파일:라인 근거 필수).
   - 빠른 잔존 검사: 삭제됐어야 할 옛 심볼/시그니처가 문서에 남아있지 않은지 grep.

7. **commit/push**:
   - **문서만** 스테이징한다(`git add docs/...`). 코드 파일은 이 스킬에서 건드리지 않는다 —
     실수로 코드가 수정됐으면 `git checkout -- <code>`로 되돌린다.
   - Obsidian 워크스페이스 파일(`.obsidian/`, 임시 노트)은 커밋하지 않는다.
   - 커밋 메시지는 `docs: ...` 접두어 + 무엇을 왜 바꿨는지. 코드 무변경임을 명시.
   - 사용자가 푸시를 원하면 현재 브랜치로 push하고, 마지막에 변경 파일·커밋 해시를 보고한다.

## 서브에이전트 위임 가이드

- **문서 신규 작성(단계 자료)**: `lecture-design` 에이전트.
- **넓은 정합성 감사**: `Explore` 에이전트 여러 개 병렬(트랙별). 각 에이전트에
  "코드 수정 금지, 불일치만 파일:라인 근거로 보고"를 지시한다.
- **문서 편집 병렬화**: 문서는 서로 독립 파일이므로 `general-purpose` 에이전트에
  문서별로 나눠 맡길 수 있다. 단, 각 에이전트에게 (a) 편집 전 실제 코드 Read로 재확인,
  (b) 문서 스타일 규칙 준수, (c) 코드 파일 수정 절대 금지를 명시한다.

## 검증용 grep 스니펫

```bash
# ASCII 박스가 이번 편집으로 새로 들어갔는지 (diff의 + 라인만)
git diff -- docs/ | grep -nP "^\+" | grep -P "[┌┐└┘├┤┬┴┼─│╔╗╚╝║═]"

# 코드 파일이 실수로 변경됐는지 (문서 스킬에선 비어 있어야 함)
git status --short src/

# MOC 위키링크가 실제 파일을 가리키는지 대조 (수동 확인)
grep -oP "\[\[[^]]+\]\]" docs/lecture/000-MOC.md | sort -u
ls docs/lecture/
```
